# TIA Portal V18 通信点表创建与导出指南

版本：V1

适用范围：当前 02 PLC Driver PoC

目标 CPU：SIMATIC S7-1500，项目默认联调型号 S7-1511-1 PN

## 1. 可以先按这份点表创建设备吗

可以。当前先冻结的是**上位机与 PLC 的通信点表**，包括 `DB100_HMI` 和 `DB101_Machine`；它不等同于电气设计中的物理 DI、DO、AI、AO 点表。相机触发、伺服使能、安全门、急停等物理地址仍需结合最终模块型号、电气原理图和安全设计确定。

配套文件：

- [PLC-POINT-LIST-V1.csv](PLC-POINT-LIST-V1.csv)：评审、核对和变更留档用点表。
- [PLC-POINT-LIST-V1.xlsx](../../outputs/2026-08-23-tia-v18-point-list-v1/PLC-POINT-LIST-V1.xlsx)：带筛选、冻结表头、状态颜色和使用说明的现场交付表。
- [CommunicationDbV1.scl](../../plc/tia-v18/CommunicationDbV1.scl)：TIA V18 外部源参考，可生成两个全局 DB。
- C# 默认地址已同步为本点表 V1。

## 2. 先创建设备

1. 新建 TIA Portal V18 项目，选择“添加新设备”。
2. 按实际硬件铭牌选择 S7-1511-1 PN 的**准确订货号和固件版本**。没有实物时可先选计划采购型号，但连接真机前必须核对。
3. 将 PROFINET 地址暂定为 `192.168.10.20/24`；上位机网卡使用同网段、不冲突的固定地址，例如 `192.168.10.10/24`。
4. CPU 机架号使用 `0`、槽位使用 `1`，与当前 C# 配置一致。
5. 项目编译通过后再进入通信 DB 创建。

## 3. 创建 DB100 和 DB101

推荐使用 SCL 外部源，减少人工录入错误：

1. 在“外部源”下添加新的 SCL 外部源，并导入 `CommunicationDbV1.scl`。
2. 从外部源生成块。
3. 检查生成的块名称分别为 `DB100_HMI`、`DB101_Machine`。
4. 如果 TIA 自动分配了其他编号，在块属性中把编号手动改为 `100` 和 `101`。
5. 打开两个 DB 的“属性 → 常规 → 属性”，确认“优化的块访问”未启用。
6. 编译软件，只接受零错误结果。
7. 打开数据块声明表的“偏移”列，逐项和 CSV 的绝对地址核对。偏移不一致时禁止下载和联调。

也可以手工创建两个全局 DB，但必须严格按照 SCL 文件中的声明顺序、类型和保留字段录入。保留字段用于固定后续变量偏移，不能删除。

## 4. CPU 通信权限

当前驱动基于 S7.NetPlus 绝对地址读写。S7-1200/1500 需要在 CPU 保护与安全设置中允许来自远程伙伴的 PUT/GET 通信；具体菜单名称可能随 CPU 固件略有差异。

该设置会扩大通信攻击面，因此只允许在隔离的控制网络中使用，并应通过工业防火墙、交换机 VLAN 和主机白名单限制访问。它不能替代 PLC 程序权限、安全 PLC 或硬接线安全回路。

## 5. V1 命令规则

- `Cmd_*` 是上位机写入的短脉冲，当前默认脉宽为 `100 ms`。
- PLC 程序必须对命令位做上升沿检测，并在处理后自行保持安全状态；不得把上位机持续在线当作安全条件。
- `Cmd_Stop` 是正常停机请求，不是急停。
- `EStop` 和 `SafetyDoor` 只是 PLC 到上位机的状态镜像，安全动作必须由安全继电器或安全 PLC 完成。
- `CommandSequence`、`CommandAckSequence`、心跳和协议版本已经纳入 V1 点表，但 PLC 侧 OB1/FB 处理逻辑仍未实现，不能仅凭变量存在宣称握手已经完成。

当前 C# 驱动已实现协议版本检查，以及可配置的命令应答和心跳监控。`EnableCommandAcknowledgement` 与 `EnableHeartbeatMonitoring` 默认保持 `false`；只有 PLC 侧完成相应 FB/OB1 逻辑并通过 TIA 编译后才能启用，否则会按设计产生应答或心跳超时。

## 6. 点表如何导出和回传

对于本项目这种 DB 内部变量，不建议只导出普通“PLC 变量表”；普通变量表与 DB 成员不是同一种对象。建议每次修改后同时保留以下三种交付物：

1. 从最终 DB 重新生成 SCL 外部源，用于版本管理和代码评审。
2. 在 DB 声明表中显示“偏移”列，将名称、类型、偏移复制到 Excel/CSV，和本项目 XLSX/CSV 对比。
3. 归档整个 TIA V18 项目为 `.zap18`，用于完整恢复硬件组态和程序。

回传联调材料时至少提供：CPU 型号、订货号、固件版本、IP、两个 DB 的 SCL 源或声明截图、编译结果，以及是否启用优化访问和 PUT/GET 权限。

## 7. 创建后核对清单

- [ ] DB100 的实际块号为 100，DB101 的实际块号为 101。
- [ ] 两个 DB 都关闭优化访问。
- [ ] `RecipeId` 为 `DB100.DBD4`。
- [ ] `CycleTime` 为 `DB101.DBD4`，`Speed` 为 `DB101.DBD8`。
- [ ] CPU IP、Rack、Slot 与上位机配置一致。
- [ ] 已在隔离测试网络中配置 PUT/GET 权限。
- [ ] 全部块编译零错误。
- [ ] 急停、安全门和 STO 不依赖上位机。
- [ ] 首次下载前由 PLC/电气工程师完成安全评审。

## 8. 后续验证顺序

1. 仅在线监控 DB101，不下发运动命令。
2. 验证上位机连接、批量读取、断线和重连。
3. 在无执行机构或安全测试模式下验证 DB100 写入和 100 ms 脉冲。
4. 增加 PLC 命令沿检测及流水号应答逻辑。
5. 执行拔网线、PLC 重启、错误地址、8 小时和 24 小时稳定性测试。

完成上述 Gate 后，才将 02 PLC Driver 标记为完成并进入 03 Camera Driver。
